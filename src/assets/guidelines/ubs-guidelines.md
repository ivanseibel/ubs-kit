# UBS Guidelines

## Purpose

UBS defines authoritative, machine-consumable behavior. UBS files must be
complete, atomic, and enforceable.

## Structure Rules

- Use the canonical 11 sections in order.
- Section headings must match the canonical names exactly.
- Each UBS file defines exactly one primary behavior.

## Assumptions

- Mark ambiguity as Assumption with a unique Assumption ID.
- Every Assumption must include a TODO question that is concrete and
  answerable.

## Language

- Canonical UBS artifacts are English only.
- Avoid idioms or ambiguous phrasing.

## Validity

- UBS files are enforceable policy; invalid UBS blocks progress.
- Do not include behavior that cannot be validated structurally.
